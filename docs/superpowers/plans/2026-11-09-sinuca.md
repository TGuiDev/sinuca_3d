# Sinuca (Bola 8) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Jogo de Bola 8 no navegador, jogador vs CPU simples, com Next + Tailwind + three.

**Architecture:** Física 2D própria (`physics/`) e regras (`rules/`) são TypeScript puro, testadas com Vitest. `ai/` usa a física para simular tacadas candidatas. `render/` desenha o estado com three puro, e um `Game` controller liga input, física, regras, IA e HUD. A UI em React/Tailwind só exibe estado.

**Tech Stack:** Next (App Router, TypeScript), Tailwind, three, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-09-sinuca-design.md`

## Global Constraints

- Next App Router + TypeScript; Tailwind apenas para a HUD; three puro (sem React Three Fiber).
- Componente do jogo carregado com `dynamic(..., { ssr: false })`.
- `physics/` e `rules/` não importam three nem React.
- Física em passo fixo; testes unitários só em `physics/` e `rules/` (mais `ai/` pela simulação).
- Fora do escopo: spin, online, sons elaborados, modelos 3D externos.
- Unidades em metros. Mesa de jogo 2.54 × 1.27, raio da bola 0.028575. Eixo x = comprimento, y = largura (em three: x→x, y→z).
- Ids de bola: 0 branca, 1–7 lisas, 8 preta, 9–15 listradas.

## Review Focus

1. Bola rápida atravessando outra bola ou tabela (tunneling): a física usa subpassos; testar tacada de força máxima.
2. Branca e bola 8 encaçapadas na mesma tacada: derrota tem prioridade; branca na mão não vale após fim de jogo.
3. Colocar a branca sobre outra bola ou fora da mesa: posição deve ser rejeitada/ajustada.
4. CPU sem tacada direta (todas as alvo bloqueadas): deve ainda devolver uma tacada válida, nunca travar o turno.
5. Desmontar o componente (navegação/HMR): loop, listeners e recursos GPU liberados.

- [ ] **Step 1: Testes** (nomes e asserts):
